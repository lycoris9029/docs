> **Documentation status:** This page describes the inspected backend source, not a verified production deployment. Implemented behavior and recommended changes are explicitly distinguished.

1. The user submits a multipart image upload (`file`) and reservation ID (`id`).
2. The backend checks the uploaded file extension against an image-extension list.
3. It saves the upload and reads the authenticated user's previously stored avatar image.
4. `AccessToken.idCard(avatarPath, uploadedFilePath)` calls Baidu's face comparison API.
5. If the returned score is at least **80**, the controller updates reservation timing and state.
6. On check-out, the controller additionally resets the associated seat status to `1` (available).

**Security note:** The face-score threshold is a software rule, not evidence of validated biometric reliability. There is no explicit liveness check in the inspected workflow; face data and third-party API calls require appropriate consent, retention and security controls.
